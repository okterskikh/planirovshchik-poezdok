# Приёмка первой версии

Дата: 15 октября 2026 года. Основание: `tz.md` 1.10 и шаги 1–4 `plan.md` с согласованными изменениями. Перед шагом 4 сохранён коммит `b37fb64`.

Поставка приложения: `index.html`, `style.css`, `script.js`. Работа через `file://`, данные — localStorage. Проверки используют только вымышленные данные и изолированные профили. Пользовательское хранилище не менялось.

## Производительность

Платформа: Windows 10.0.19044, Intel Pentium Silver N5030 @ 1.10 GHz, 4 логических процессора, 7,65 GiB RAM. Headless Chrome/Edge, без искусственного замедления. Набор: 1000 задач, 200 мест, 5000 событий, размер JSON по UTF-16 — 2 411 420 байт; описания до 200, заметки до 100 символов.

Проведён прогрев и пять измерений каждой операции. Все исходные значения сохранены в `performance-results.json`; таблица содержит медианы в миллисекундах.

| Операция | Chrome | Edge | Цель |
| --- | ---: | ---: | ---: |
| Перезагрузка сохранённого приложения | 785,5 | 720,8 | ≤ 2000 |
| Разбор CSV и подготовка предпросмотра | 721,2 | 674,8 | ≤ 2000 |
| Поиск одной задачи | 55,9 | 52,0 | ≤ 200 |
| Возврат к полной выборке | 95,0 | 81,7 | ≤ 200 |
| Изменение готовности с сохранением и обновлением UI | 274,2 | 282,5 | ≤ 300 |

Первый прогон выявил медленную отрисовку полной выборки. Для списков свыше 80 задач подробные карточки отрисовываются при приближении к видимой области или фокусе. Поиск и массовые действия используют весь набор. Отдельно проверены карточки 500 и 999, клавиатурный фокус и выбор всех 1000 задач. Цели ТЗ заданы для медиан: отдельные значения сохранения могут превышать 300 мс и доступны в JSON измерений.

## Печать и артефакты

`step4-day-chrome.pdf` / `step4-day-msedge.pdf` — одна страница A4. `step4-long-chrome.pdf` / `step4-long-msedge.pdf` — шесть страниц; текст последней содержит «КОНЕЦ ПОРУЧЕНИЯ». Проверено извлечением текста через pypdf. Обычная первая страница и последняя страница длинного документа отрендерены через pypdfium2 и просмотрены: `step4-pdf-page.png`, `step4-pdf-long-last.png`. Управления и истории на печати нет.

Отчёты браузерных проверок — файлы `*-results.json`, вывод core — `step4-core-results.txt`. Тестовые библиотеки используются только при разработке, приложению не нужны.

## Ограничения и ручная оценка

- Chrome/Edge 120 не установлены; их проверка не заявляется. Проверены актуальные указанные версии и имитация отсутствия Windows-1251.
- Телефон и объединение JSON — отдельный шаг 5, не выполнялись. Проверка ширины 360 px не означает проверку запуска на телефоне.
- Физический принтер недоступен; проверены браузерная печать в PDF, размер A4, текст и растровые страницы.
- Приложение инициирует скачивание и сохраняет снимок файла, но не может проверить физическое сохранение пользователем или фактическое обновление внешней Google-таблицы. Для этого предусмотрено ручное подтверждение выбранной выгрузки.
- Пользователю остаются внешний вид, удобство рабочего дня, понятность экспорта/напоминания и читаемость печатного чек-листа. Функциональные проверки на пользователя не перекладываются.
