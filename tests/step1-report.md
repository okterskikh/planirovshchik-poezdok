# Отчёт о проверке шага 1

Дата: 15 октября 2026 года. Основание: `../tz.md` и шаг 1 `../plan.md`.

## Итог

- 23 теста предметной логики: пройдены.
- 38 браузерных сценариев: по 19 в Chrome и Edge, пройдены.
- 2 проверки сохранения после полного закрытия и повторного запуска браузера: пройдены.
- Ошибки JavaScript и HTTP-запросы приложения в браузерных сценариях: отсутствуют.
- Синтаксис `script.js`: проверен через `node --check`.

## Среда

- Windows, Node.js 24.19.0.
- Chrome 155.0.8059.39.
- Edge 155.0.4283.45.
- Локальный запуск `file://`; отдельные тестовые профили. Данные пользователя не используются.
- Playwright из установленного bundled runtime; библиотека нужна только тестам. Приложение запускается без неё.

## Повторение проверок

Из папки проекта:

```powershell
node --check script.js
node --test --test-isolation=none tests/step1-core.test.cjs
node tests/step1-browser.cjs
```

Браузерный набор запускает установленные Chrome и Edge. Пути к Playwright соответствуют bundled runtime текущей рабочей среды. Профили проверки полного закрытия создаются в системной временной папке и удаляются только после проверки, что путь принадлежит созданной тестовой папке.

## Материалы

- `fixtures/tasks.csv`: вымышленные задачи из базового примера ТЗ.
- `fixtures/places.csv`: вымышленный справочник с заголовками в четвёртой физической строке.
- `step1-core-results.txt`: вывод тестов логики.
- `step1-browser-results.json`: список проверок и версии браузеров.
- `step1-chrome.png`, `step1-msedge.png`: снимки списка задач.

Windows-1251, другие разделители, многострочные поля, неизвестные значения и ошибочные файлы генерируются тестом в памяти. Плохие даты, дубли ID, конфликты, отмена и возврат, повреждённое хранилище и ошибка квоты проверяются без реальных клиентских данных.

## Границы проверки

Минимальные версии браузеров 120 не установлены; этот отчёт подтверждает только перечисленные реальные версии. Проверка экрана 360 px подтверждает компоновку списка, а не работу на реальном телефоне. Нагрузочные измерения финальной версии относятся к шагу 4.

Проверка внешнего вида включает просмотр снимков разработчиком. Субъективную оценку удобства, читаемости и понятности рабочего процесса оставляем пользователю. Повторная ручная проверка логики, кнопок, сохранения и экспорта JSON не требуется.
