# Техническое задание: планировщик поездок и задач

**Версия:** 1.12
**Дата:** 16 октября 2026 года

## 1. Назначение и этапы

Планировщик предназначен для одного исполнителя, который доставляет документы и выполняет поручения в судах, судебных участках и подразделениях ФССП.

Постановщик и руководитель продолжают работать в Google-таблице «Задачи и калькулятор поездок». Исполнитель получает задачи через Excel (.xlsx) или CSV, планирует поездки, отмечает результаты и передаёт их обратно в таблицу.

### Первая версия

Обязательные функции:

- импорт задач и справочника из Excel (.xlsx) и CSV через выбор файла или перетаскивание;
- план дня и недели;
- группировка задач по месту назначения;
- приоритеты и ручной порядок поездок;
- перенос задач и поездок;
- автоматический перенос невыполненных задач;
- подготовка документов;
- локальные заметки;
- выполнение и неудачные попытки;
- поиск и фильтры;
- отчёты об импорте;
- экспорт результатов;
- печать;
- резервное копирование и восстановление JSON.

Поддерживаемая рабочая среда первой версии — компьютер. Мобильная компоновка предусматривается, но запуск и работа на реальном телефоне не являются критериями приёмки первой версии.

### Второй этап

После отдельной проверки запуска на телефоне:

- поддержка реального мобильного устройства;
- обмен между компьютером и телефоном;
- объединение JSON-копий с выбором различий по группам данных.

Графы версий и распределённая синхронизация не реализуются.

### Технические ограничения

Результат первой версии — ровно три файла:

- `index.html`;
- `style.css`;
- `script.js`.

Обычные HTML, CSS и JavaScript. Без сборки, фреймворков, CDN и внешних библиотек. Данные — в localStorage. Запуск — открытием HTML из постоянной папки.

Код `script.js` разделить на логические блоки: модель, хранение, CSV, планирование, результаты, экспорт, отображение. Все изменения данных проводить через единый обработчик операций.

Не входят: сервер, база данных, авторизация, прямой доступ к Google Drive, калькулятор поездок, автоматический маршрут, файлы документов, подзадачи, системные уведомления.

## 2. Участники и источники данных

Постановщик добавляет и исправляет исходные сведения в Google-таблице. Руководитель назначает приоритеты, отменяет задачи и исправляет результаты, включая возврат задачи в работу.

Внутри приложения работает только исполнитель.

| Группа данных | Основной источник |
|---|---|
| ID, клиент, документ, постановщик, описание | Google-таблица |
| Место, адрес, метро, расположение | Таблица и её справочник |
| Исходный приоритет | Google-таблица |
| Приоритет исполнителя | Приложение; при наличии используется вместо исходного |
| Планируемая дата, порядок поездок | Приложение |
| Готовность документов, локальная заметка | Приложение |
| Результат выполнения и попытки | Приложение; изменения таблицы принимаются по правилам импорта |
| Отмена и возврат задачи | Google-таблица |

Исполнитель не создаёт задачи, не меняет исходные сведения, не редактирует справочник вручную, не отменяет и не возвращает завершённые задачи. Исполнитель может назначать собственный приоритет активным задачам по правилам раздела 5.3.

Он может импортировать, планировать, оставлять локальные заметки, отмечать документы и результаты, печатать и экспортировать.

### Регламент обмена

1. Перед составлением плана исполнитель загружает актуальную Excel-книгу (.xlsx) или CSV задач. В Excel-книге выбирает нужный лист.
2. После уведомления руководителя об изменениях исполнитель повторяет импорт.
3. В конце рабочего дня исполнитель экспортирует изменившиеся результаты и вручную переносит их в Google-таблицу по ID.
4. После проверки переноса подтверждает его в приложении.
5. Перед заменой файлов приложения, сменой браузера или папки создаёт JSON-копию.
6. Исправления ошибочного выполнения делаются в таблице и принимаются следующим импортом.

Порядок строк таблицы не используется для сопоставления.

## 3. Модель данных и словари

### 3.1. Общий контейнер

```text
schemaVersion
workspaceId
revision
tasks
destinations
dayOrders
destinationAliases
importMappings
excludedDates
lastConfirmedResultsExport
lastBackupExport
```

- `schemaVersion`: целое число, первая версия — `1`.
- `workspaceId`: UUID рабочей области.
- `revision`: счётчик успешных изменений.
- `dayOrders`: порядок мест для каждой даты.
- `excludedDates`: вручную исключённые даты.
- Необязательные служебные поля первой версии: `pendingResultExports` — ожидающие подтверждения выгрузки с ID, временем и снимками результатов; `backupContentHash` — отпечаток содержимого последней JSON-копии без метаданных копирования; `backupSnoozeUntil` — дата возобновления напоминания. Отсутствие полей в старой копии допустимо, схема остаётся 1.
- Состояние интерфейса и незавершённые формы не являются частью предметных данных.

Основной ключ хранения: `tripPlanner.state.v1`.

### 3.2. Задача

| Поле | Содержание |
|---|---|
| `id` | Постоянный ID из таблицы |
| `source` | Постановщик, дата постановки, клиент, документ, описание, место, приоритет |
| `plannedDate` | Дата поездки или `null` |
| `firstPlannedDate` | Первая назначенная дата или `null` |
| `documentsReady` | Булево значение |
| `localNote` | Свободная заметка исполнителя |
| `localPriority` | Необязательный приоритет исполнителя: `normal`, `high`, `urgent` или `null`. Отсутствие поля и `null` означают использование `source.priority` |
| `result` | Исход, дата и комментарий последнего результата |
| `lastCsvResult` | Снимок нормализованного результата последней принятой таблицы: Excel или CSV; историческое имя поля сохраняется |
| `history` | События с уникальными ID |
| `lastConfirmedExportResult` | Результат, перенос которого в таблицу подтверждён |

`source` содержит:

```text
createdBy, createdDate, client, documentNumber,
destinationId, description, priority
```

`result` содержит:

```text
outcome, date, comment
```

`outcome`: `none`, `failed`, `completed`, `cancelled`.

Пользовательский статус вычисляется:

- `completed` → выполнена;
- `cancelled` → отменена;
- `failed` → не удалось выполнить;
- `none` и есть дата поездки → запланирована;
- `none` и даты нет → новая.

Это исключает конфликт между статусом «новая» в таблице и локальным назначением даты.

Даты хранить как `YYYY-MM-DD`. Пустые даты — `null`, пустые тексты — `""`. Номера документов хранить строками.

### 3.3. Место

```text
id, name, metro, address, location, aliases
```

Нормализация названий: обрезать крайние пробелы, схлопнуть повторные пробелы, привести к нижнему регистру только для сравнения.

Не удалять номера и смысловые части. Совпадение адреса само по себе не означает совпадение учреждения.

### 3.4. Статусы

| Внутреннее значение | Интерфейс и экспорт | Допустимые значения CSV |
|---|---|---|
| `new` | Новая | новая |
| `planned` | Запланирована | запланирована |
| `failed` | Не удалось выполнить | не удалось выполнить |
| `completed` | Выполнена | выполнена, выполнено |
| `cancelled` | Отменена | отменена, отменено |

Регистр и крайние пробелы при импорте не учитывать.

### 3.5. Приоритеты

| Значение | Интерфейс и экспорт | Допустимые значения CSV | Ранг |
|---|---|---|---|
| `urgent` | Срочно | срочно, срочный, срочная | 0 |
| `high` | Высокий | высокий, высокая | 1 |
| `normal` | Обычный | обычный, обычная, пусто | 2 |

Неизвестные значения требуют явного сопоставления в мастере импорта.

### 3.6. История

Событие содержит ID, время, тип и минимальные необходимые данные изменения. Не сохранять полный снимок задачи при каждой операции.

Типы событий:

- назначение и снятие даты;
- ручной и автоматический перенос;
- изменение готовности;
- изменение заметки;
- результат попытки;
- выполнение;
- отмена и возврат из таблицы;
- изменение исходных сведений;
- отмена разрешённого локального действия.

Историю не удалять автоматически.

## 4. Интерфейс

Разделы:

1. «Неделя».
2. «День».
3. «Задачи».
4. «Обмен данными».
5. «Настройки».

В разделе «Задачи» — быстрые представления «Незапланированные», «Активные», «Выполненные», «Отменённые», «Все». Отдельного раздела «Архив» нет.

### Неделя

Заголовок блока незапланированных задач закреплён при прокрутке его списка. Блок выделен светлым синим фоном и контуром, шапка — отдельной непрозрачной заливкой; название и счётчики показываются раздельно.

Раздел «Неделя» открывается первым при запуске и перезагрузке страницы; в навигации он отмечен активным.

Семь колонок, понедельник–воскресенье. Навигация назад, вперёд и «Сегодня».

Над недельной лентой расположена заметная горизонтальная полоса прокрутки, синхронизированная с прокруткой дней. Она закрепляется у верха окна при вертикальной прокрутке, чтобы оставаться доступной при длинных карточках на ноутбуке. Нижняя полоса сохранена. Верхняя полоса поддерживает клавиатуру; её диапазон обновляется при выборе дня и изменении размера окна.

В разделах «Неделя» и «День» блок незапланированных задач расположен в левой панели рабочего пространства под навигацией, а не над календарём. На компьютере панель шириной 300 px закреплена в пределах высоты окна; группы судов размещаются в одну колонку, список имеет собственную вертикальную прокрутку. Компактные отступы сохранены. В остальных разделах этот блок скрыт. На экранах до 700 px панель становится верхним блоком, а область незапланированных задач ограничена высотой 240 px. Перенос групп и отдельных задач в календарь, раскрытие состава и кнопки назначения даты остаются доступными.

Выбранная дата в недельном плане показана немного более широкой карточкой: 230 px против 205 px у остальных дней, минимальная высота 250 px против 240 px. Размер текста и внутренние отступы одинаковы; выделение поддерживается границей и фоном. Недельная лента автоматически прокручивается так, чтобы выбранный день находился по центру её видимой области, включая понедельник и воскресенье. Хронологический порядок дней сохраняется. Выбор даты, «Сегодня», переход недели и нажатие заголовка другого дня обновляют выделение и центрирование внутри недельного плана. Раздел «День» открывается через навигацию. На узком экране недельная лента также прокручивается горизонтально с теми же размерами карточек. Изменение выбранной даты не меняет расписание задач.

В разделах «Неделя» и «День» блок незапланированных активных задач группируется по ID учреждения. Для каждого суда/учреждения показывать название, количество задач, максимальный приоритет с цветовой подсветкой и раскрываемый состав с клиентом, документом, поручением и приоритетом. Группы упорядочивать по названию учреждения, задачи внутри — по правилу раздела 5.3. Уже запланированные, выполненные и отменённые задачи в блок не включать.

Группу можно перетащить за обозначение «Весь суд на день» на день календаря либо назначить дату кнопкой «Назначить день всему суду». Переносятся все активные незапланированные задачи этой группы; задачи этого суда на других датах не меняются. В раскрытом составе доступны отдельное перетаскивание и назначение даты задачи. При попадании в существующую поездку того же суда задачи объединяются. Правила дат, подтверждения выходных, сохранения и отмены общие с разделом 5.2. После распределения всей группы она исчезает из блока; когда групп нет, показывать сообщение, что все активные задачи распределены.

Карточка поездки:

- название места;
- адрес и метро;
- расположение;
- максимальный приоритет активных задач;
- число задач;
- готовность документов;
- число накопившихся задач;
- раскрытие состава;
- изменение даты и порядка.

### День

Поездки в выбранной последовательности. В каждой задаче:

- клиент и документ;
- содержание поручения;
- постановщик и дата постановки;
- приоритет и статус;
- готовность документов;
- локальная заметка;
- последний результат;
- доступ к истории.

Первая запланированная дата показывается в деталях и истории, а не занимает место в компактной карточке.

### Список задач

Задачи отображаются сеткой отдельных карточек: 4 колонки при ширине окна от 1280 px, 5 — от 1650 px. На меньших экранах количество колонок уменьшается до 3, 2 или 1; до 700 px — одна колонка. Текст не обрезать, длинные значения переносить, детали и историю открывать внутри карточки. Пустое состояние занимает всю ширину сетки. Это оформление списка задач, а не изменение недельного плана или списка учреждений в диалоге.

Верхние плашки являются кнопками, а не только счётчиками:

- «Активных задач» — число новых, запланированных и неудачных задач. Нажатие открывает все активные задачи и сбрасывает прежние фильтры.
- «Мест назначения по активным задачам» — число уникальных учреждений, по которым есть хотя бы одна активная задача. Выполненные и отменённые задачи, а также неиспользуемые места справочника не учитываются. Нажатие открывает список таких учреждений с числом активных задач и имеющимися адресными сведениями. Кнопка учреждения открывает только его активные задачи.
- «Выполнено» — число выполненных задач. Нажатие открывает выполненные задачи и сбрасывает прежние фильтры.

Счётчики отражают весь сохранённый набор, независимо от текущих фильтров. При нулевых значениях кнопки доступны и показывают понятное пустое состояние. Переключение представлений и просмотр мест не меняют хранилище. Кнопки доступны мышью и клавиатурой.

Поиск по клиенту, документу, поручению, месту, адресу, постановщику и локальной заметке.

Фильтры:

- статус;
- место;
- постановщик;
- приоритет;
- готовность документов;
- диапазон дат постановки;
- диапазон дат поездки;
- расположение.

Фильтры комбинируются. Отображаются количество результатов и сброс фильтров.

### Настройки

- вручную исключённые даты;
- напоминания о резервном копировании;
- сведения об объёме хранения;
- версия приложения и схемы.

Светлый деловой интерфейс. Цвета сопровождаются подписями. Все действия доступны кнопками и клавиатурой.

## 5. Планирование и автосортировка

### 5.1. Поездки

Поездка определяется парой:

`дата + ID места`

В одном дне не более одной поездки в одно место. В неё входят все активные задачи с этой датой и местом.

Выполненные и отменённые задачи не входят в активный состав.

### 5.2. Ручные действия

Исполнитель может:

- назначить дату;
- перенести отдельную задачу;
- перенести все активные задачи поездки;
- снять дату;
- изменить порядок поездок.

Для этих действий доступны перетаскивание на компьютере и равноценные кнопки.

В неделе можно захватывать название/неинтерактивное содержимое карточки суда для переноса всей поездки и текст вложенной карточки для переноса одной задачи; значки ↗ сохраняются. Кнопки, поля и раскрытие состава не начинают перенос. Колонки дней растянуты до высоты самого длинного дня, чтобы нижнюю карточку можно было отпустить в соседний день на той же высоте.

На время захвата слева открывается закреплённая панель с датами текущей отображаемой и следующей недели, а также зоной возврата в незапланированные. На дату можно отпустить задачу или поездку, в том числе из нижней части длинного дня. Календарь не переключать и не перерисовывать до отпускания: захват должен сохраняться. Панель не перекрывает основные колонки и появляется только при переносе; после отпускания или Escape скрывается. Итоговое сообщение содержит дату назначения. Для выходных, исключённых и прошедших дат действуют общие правила.

Прошедшую дату вручную назначать нельзя. Выходные и вручную исключённые даты можно выбрать после предупреждения.

При переносе в существующую поездку задачи объединяются. Пустая поездка исчезает.

Новые задачи поступают в незапланированные. Автоматического назначения даты новым задачам нет.

### 5.3. Приоритеты и порядок

Исполнитель выбирает «Обычный», «Высокий» или «Срочно» у отдельной активной задачи в списке и внутри раскрытого суда. В карточке поездки доступен выбор приоритета сразу для всех активных задач этого суда на отображаемую дату. Другие дни и завершённые задачи не затрагиваются. Групповая установка записывает значение каждой выбранной задаче; оно сохраняется при последующем переносе задачи на другой день.

Приоритет исполнителя хранится в `localPriority`, отдельно от `source.priority`. Используемый приоритет — `localPriority`, если задан, иначе `source.priority`. Импорт обновляет исходный приоритет, сохраняя выбор исполнителя. Действие «Из таблицы» снимает локальный выбор; для суда снимает его у всех активных задач на выбранный день. Исходная таблица автоматически не изменяется. Список, фильтры, сортировка и максимальный приоритет поездки используют используемый приоритет. Полная JSON-копия сохраняет `localPriority`; старые копии без поля принимаются без миграции. Во втором этапе поле выбирается отдельной группой «Приоритет исполнителя» при объединении копий по разделу 13.

Высокий приоритет выделяется светлым жёлтым фоном и акцентной границей, срочный — светлым красным. Подсвечиваются карточка задачи в списке и внутри суда, незапланированная карточка и карточка поездки по максимальному приоритету. Текстовое значение остаётся видимым, чтобы цвет не был единственным обозначением. Изменения записываются в историю и сохраняются после перезагрузки. Они завершают доступность отмены предыдущего действия; отдельная отмена приоритета не требуется, значение можно выбрать повторно.

Автосортировка выполняется при:

- добавлении задач в день;
- переносе задач;
- изменении приоритета через импорт Excel или CSV;
- назначении или сбросе приоритета исполнителем;
- автоматическом переносе;
- завершении или отмене задачи, если изменился приоритет поездки.

Перед сортировкой создать последовательность:

1. существующие поездки в сохранённом порядке;
2. новые поездки по нормализованному названию места;
3. при одинаковом названии — по ID.

Выполнить стабильную сортировку этой последовательности по рангу приоритета. Приоритет поездки — максимальный приоритет её активных задач.

**Пример:** сохранён порядок A — обычный, B — высокий, C — высокий. Добавлена D — высокий. Результат: B, C, D, A.

После автосортировки разрешена произвольная ручная перестановка. Следующее событие автосортировки снова применяет правило. Показать сообщение о перестановке.

Задачи внутри поездки сортировать по приоритету, затем клиенту с русским сравнением строк, затем ID.

## 6. Автоматический перенос

Рабочие дни — понедельник–пятница, кроме вручную исключённых дат. Автоматический календарь государственных праздников отсутствует.

Найти все активные задачи с датой раньше сегодняшней. Перенести на первую доступную рабочую дату, начиная с сегодняшней.

Примеры:

- в обычный вторник задачи понедельника переходят на вторник;
- в субботу задачи пятницы переходят на понедельник;
- если понедельник исключён, переходят на вторник;
- после отпуска накопившиеся задачи переходят сразу на ближайшую актуальную рабочую дату.

Проверки:

- при загрузке;
- при возвращении видимости вкладки;
- при получении фокуса;
- раз в минуту.

Календарную дату вычислять в `Europe/Moscow`.

Не переносить выполненные, отменённые, незапланированные и будущие задачи.

Сохранять приоритет, готовность, заметку и результаты попыток. Записывать один фактический переход со старой даты на новую. Повторные проверки не создают дублей.

### Защита формы

Если открыта форма результата или редактирования заметки:

- не перерисовывать и не сбрасывать её;
- отложить автоперенос до сохранения или закрытия;
- после сохранения результата выполнять перенос по актуальному состоянию.

### Накопившийся день

Не ограничивать число задач и не распределять их автоматически по будущим дням.

При более чем 10 поездках или 30 активных задачах показать предупреждение о большой нагрузке. Предоставить массовый выбор задач и перенос на выбранную дату.

При автопереносе сортировка сегодняшнего дня выполняется по правилам раздела 5.3. Ручной порядок сохраняется внутри одинакового приоритета.

## 7. Документы, заметки, результаты и отмена действий

### Документы

Переключатель «Документы готовы» у каждой задачи. Групповые действия для поездки — отметить или снять готовность.

Готовность не блокирует выполнение.

### Локальная заметка

Свободное поле до 2 000 символов: кабинет, окно, контакт, особенности приёма и другие сведения.

Не меняет исходное поручение, не экспортируется как комментарий результата, сохраняется при CSV-импорте. Показывается в карточке, поиске и печати.

### Выполнение

Форма:

- дата, по умолчанию сегодня;
- необязательный комментарий;
- подтверждение.

Будущая дата недопустима. После подтверждения задача завершена и не переносится.

### Неудачная попытка

Дата и обязательная причина до 4 000 символов. Пробелы не считаются причиной.

Задача остаётся активной. Последняя попытка показывается в карточке, предыдущие — в истории. Предложить выбрать новую дату.

### Отмена и возврат

Только из таблицы:

- отмена архивирует задачу;
- возврат делает её активной и незапланированной;
- готовность документов при возврате сбрасывается;
- история и локальная заметка сохраняются.

### Отмена последнего локального действия

Поддержать для:

- планирования и переноса;
- изменения порядка;
- готовности документов;
- локальной заметки.

Кнопка доступна до следующей изменяющей операции, импорта, автопереноса или перезагрузки. Отмена записывается в историю.

Подтверждённое выполнение, неудачная попытка, импорт и восстановление JSON этим способом не отменяются. Перед выполнением обязательно подтверждение.

## 8. Импорт Excel и CSV

### 8.1. ID

Столбец «ID задачи» обязателен. Его добавляет в исходную Google-таблицу сотрудник, который ставит задачи. Он же назначает ID каждой новой строке до выгрузки, например постоянной строкой `TASK-000001`. ID находится в строке соответствующей задачи, в отдельном столбце «ID задачи», и входит в Excel- или CSV-выгрузку. Для ранее созданных задач ID заполняет ответственный постановщик.

ID:

- уникален;
- не меняется при сортировке и исправлениях;
- не используется повторно для другой задачи;
- не вычисляется из текущего номера строки.

Для существующих строк допускается однократное заполнение последовательности с фиксацией значений. Генерация ID через формулы с пересчётом и сопоставление строк без ID не используются.

Пустые или повторяющиеся ID блокируют импорт строк с данными задач. Приложение не создаёт ID задач за пользователя.

До проверки ID пропускать пустые заготовки: строки без исходных сведений и результата, содержащие только пустые поля, FALSE/0/НЕТ в отметке выполнения, обычный приоритет, статус «Новая»/«Запланирована» или заранее зарезервированный ID. Несопоставленные столбцы не создают задачу. Такие строки не требуют ID и не участвуют в проверке дублей. Показывать их количество в проверке и отчёте. Если есть клиент, поручение, документ, другие исходные сведения, результат или отметка TRUE, строка не считается пустой и проходит обязательные проверки.

### 8.2. Мастер

1. Тип файла.
2. Выбор файла кнопкой или перетаскиванием; кодировка и разделитель для CSV, выбор листа для Excel.
3. Выбор заголовков и сопоставление полей.
4. Предварительный просмотр.
5. Проверка.
6. Сопоставление мест.
7. Разбор конфликтов.
8. Итоговый отчёт.
9. Подтверждение.

До подтверждения хранилище не меняется.

Поддержка:

- UTF-8 с BOM и без него;
- Windows-1251 через явный выбор;
- запятая, точка с запятой, табуляция;
- кавычки, удвоенные кавычки, многострочные поля.

Для справочника искать заголовки в первых десяти строках. Если вариантов несколько, предложить выбор.

### 8.3. Поля

Использовать исходные заголовки:

`ID задачи`, `Кто направил`, `Дата направления`, `Клиент`, `Номер листа`, `Место направления`, `Метро`, `Адрес`, `Расположение`, `Задача (сколько заявлений, что сделать)`, `Приоритетность`, `Статус`, `Выполнение`, `Дата выполнения`, `Комментарий`.

Обязательные значения: ID, клиент, название суда или другого учреждения из столбца «Место направления». Адрес, метро и расположение необязательны. Пустое описание либо отсутствие столбца описания не препятствуют импорту и показу задачи в планировщике: описание сохраняется пустым, допускается только информационное предупреждение.

Даты: `ДД.ММ.ГГ`, `ДД.ММ.ГГГГ`, `YYYY-MM-DD`. Двузначный год — 2000–2099. Несуществующие даты отклонять.

Признак выполнения: TRUE/1/ДА или FALSE/0/НЕТ/пусто.

Если статус отсутствует, признак выполнения определяет результат. Если оба заполнены и противоречат друг другу, требуется решение.

«Новая» и «Запланирована» нормализуются в результат `none`; локальная дата не импортируется.

Для завершённых задач дата результата обязательна. Для неудачной попытки обязательны дата и причина.

### 8.4. Трёхстороннее сравнение результатов

Обозначения:

- B — результат последнего принятого CSV;
- L — текущий локальный результат;
- C — результат нового CSV.

Сравнивать нормализованные группы `outcome + date + comment`. Правила одинаковы для Excel и CSV; B и C обозначают предыдущую и новую принятые таблицы независимо от формата.

| Условие | Действие |
|---|---|
| C = B | Сохранить L |
| L = B | Принять C |
| L = C | Сохранить совпадающий результат |
| L ≠ B, C ≠ B и L ≠ C | Показать конфликт |

Если снимка B ещё нет, первичный импорт устанавливает результат из CSV.

После принятого импорта сохранить C как новый B независимо от выбранной текущей версии. Это предотвращает повторные конфликты с неизменившимся файлом.

Отмена из таблицы применяется после отдельного подтверждения и имеет приоритет. Возврат завершённой задачи отражается в итоговом отчёте явно.

Расписание, готовность и заметка сохраняются. Отсутствие задачи в CSV не означает удаление.

### 8.5. Места

Главная сущность назначения — сам суд или другое учреждение. Его название берётся из столбца «Место направления». По нормализованному названию автоматически находится существующее учреждение либо создаётся новое: вручную назначать место каждому суду не требуется.

Адрес, метро и расположение берутся только из загружаемых сведений или уже принятого справочника для того же учреждения. Если сведений нет, поля остаются пустыми; приложение не подбирает их по догадке. Одинаковое название после удаления лишних пробелов и сравнения без учёта регистра соответствует одному учреждению. Разные названия автоматически не объединяются по адресу или сходству текста.

Отдельный импорт справочника необязателен. Он полезен для предварительной загрузки и обновления адресов и метро. Ранее сохранённые привязки вариантов названий сохраняются и продолжают работать; при обычном импорте новые привязки вручную не запрашиваются. Противоречащие явно заполненные адресные сведения показываются для выбора, как реальные изменения данных, а не как обязательное назначение суда.

Обновление справочника не удаляет отсутствующие места.

### 8.6. Отчёт

Показать:

- новые задачи;
- изменённые исходные сведения;
- изменения приоритетов;
- отменённые и возвращённые задачи;
- изменённые результаты;
- переставленные дни;
- новые и изменённые места;
- пропущенные ошибочные строки.

Каждая запись содержит ID и значения до/после.

Отчёт последнего импорта доступен до следующего импорта и хранится компактно, без полного дублирования задач.

Строки с обычными ошибками можно исключить после подтверждения. Неразрешённые конфликты и ошибки ID блокируют применение.

### 8.7. Excel (.xlsx) и перетаскивание

- Excel (.xlsx) — основной удобный формат загрузки. CSV остаётся дополнительным форматом. Книгу можно скачать из Google-таблицы через «Файл → Скачать → Microsoft Excel (.xlsx)».
- Файл можно выбрать кнопкой или перетащить в область загрузки мастера. Перетаскивание на основную страницу открывает мастер, по умолчанию для задач; тип данных можно сменить на справочник.
- Принимается один файл за раз. Перетаскивание нового файла во время проверки или подтверждения не заменяет текущий импорт: пользователь сначала завершает либо закрывает форму.
- После чтения книги показывается выбор листа. Для задач по умолчанию выбирать лист «задачи», для справочника — «справочник» без учёта регистра. Если такого листа нет, выбирать первый и давать возможность сменить его.
- Из выбранного листа читать значения ячеек, включая текст, многострочный текст, логические значения, Excel-даты и номера документов с простым форматом ведущих нулей `000…`. Пустые строки игнорировать, номера физических строк сохранять для ошибок.
- Формулы не вычисляются и не исполняются; используется сохранённый результат. Если у формулы нет сохранённого результата или Excel сообщает ошибку ячейки, импорт листа останавливается с адресом ячейки. Пользователь должен пересчитать и сохранить книгу.
- Старый двоичный .xls, .xlsm/.xlsb и зашифрованные книги не поддерживаются. Для .xls показать инструкцию сохранить файл как обычную книгу .xlsx без пароля. Защита листа от редактирования сама по себе не препятствует чтению данных.
- Обработка происходит в браузере без загрузки на сервер, CDN и дополнительных файлов приложения. XLSX читается встроенными браузерными средствами ZIP/XML; сторонняя библиотека в приложении не добавляется.
- Технические пределы: файл до 50 MiB, суммарные распакованные прочитанные XML-части до 50 MiB, до 200 000 ячеек в выбранном листе. При превышении либо повреждении файла показывать ошибку; текущее хранилище не меняется.
- При замене файла, типа данных или листа сбрасывать решения конфликтов и исключения строк предыдущего просмотра. ID, валидация, сопоставление мест, отчёт и трёхстороннее сравнение после чтения Excel такие же, как для CSV.

## 9. Экспорт, копии и хранение

### 9.1. Результаты CSV

Варианты:

- изменившиеся после последней подтверждённой передачи;
- результаты за период;
- все результаты.

Столбцы:

`ID задачи;Клиент;Номер листа;Статус;Выполнение;Дата выполнения;Комментарий`

UTF-8 с BOM, разделитель `;`, даты `ДД.ММ.ГГГГ`.

У выполненных TRUE, у остальных FALSE.

Экспорт изменений сравнивает текущий результат с `lastConfirmedExportResult`. Простое скачивание не помечает данные переданными.

После ручного обновления таблицы пользователь подтверждает передачу выбранной выгрузки. Запоминаются значения, содержащиеся именно в ней, даже если задача уже изменилась после скачивания.

### Защита от формул

Если текст после ведущих пробелов начинается с `=`, `+`, `-`, `@`, добавить в начало апостроф.

Объяснить в интерфейсе: CSV защищён от выполнения формул; в некоторых программах апостроф будет виден, в том числе перед телефоном или комментарием с дефисом.

При импорте собственного экспорта убрать ровно один защитный апостроф только перед таким значением. JSON хранит исходный текст без защитного преобразования.

Собственный CSV результатов распознаётся по семи указанным заголовкам в заданном порядке. Его можно загрузить прежним мастером импорта: обновляются только результаты существующих ID по общим правилам сравнения, исходные сведения берутся из сохранённой задачи. Неизвестный ID блокирует применение. Это не способ создания новых задач. Защитный апостроф снимается только перед значением, начинающимся после пробелов с `=`, `+`, `-`, `@`; остальные апострофы остаются.

Каждая скачанная выгрузка получает уникальный ID, включённый в имя файла и список ожидающих передачи. Снимки сохраняются в localStorage и JSON-копии, поэтому подтверждение доступно после перезагрузки. При подтверждении снимки выбранной выгрузки записываются в `lastConfirmedExportResult`, ожидающая запись удаляется. Пустую выборку не скачивать, показать сообщение.

### 9.2. JSON первой версии

Поле выбора резервной копии не ограничивать атрибутом `accept`: на iPhone тип скачанного файла может определяться неоднозначно. Принимать для проверки любой выбранный файл, но применять только после успешного разбора JSON, проверки модели и подтверждения замены. Расширение и MIME не заменяют проверку содержимого. Если файл недоступен в облачном провайдере iPhone, интерфейс предлагает скопировать его в «На iPhone» и выбрать оттуда.

Экспортировать все данные, включая историю и снимки импорта.

Импорт JSON первой версии — только полное восстановление:

- проверить формат и версию;
- показать объём и количества;
- предложить скачать текущую копию;
- подтвердить замену;
- применить одной операцией.

Не объединять незаметно две копии.

### 9.3. Напоминания

Показать ненавязчивое напоминание:

- если после последней копии есть изменения и прошёл день;
- после импорта, если копия ещё не создана;
- при приближении к ограничению хранения.

Отложить напоминание можно до следующего дня. Успешная выгрузка JSON обновляет дату резервной копии.

Для сравнения использовать отпечаток содержимого без `revision` и метаданных резервного копирования: одно отложение или сама копия не считается изменением предметных данных. Для напоминания «прошёл день» использовать смену московской календарной даты. Порог объёма продолжает отображаться отдельным предупреждением даже при отложенном напоминании.

### 9.4. Объём

Расчётный набор: 1 000 задач, 200 мест, 5 000 событий.

Показывать оценку размера сериализованного контейнера: число UTF-16 единиц × 2. Это оценка приложения, а не точное измерение браузерной квоты.

- от 2 MiB — предупреждение;
- свыше 4 MiB — не применять увеличивающую размер операцию, предложить экспорт кандидата в JSON;
- любую ошибку записи обрабатывать независимо от оценки.

Автоматически удалять задачи или историю запрещено.

Реальная квота зависит от среды; браузерную ошибку считать окончательным признаком невозможности записи. [Документация MDN о квотах](https://developer.mozilla.org/en-US/docs/Web/API/Storage_API/Storage_quotas_and_eviction_criteria).

### 9.5. Надёжность

Перед записью сформировать и проверить новый контейнер. Интерфейс обновлять как сохранённый только после успешного `setItem`.

При ошибке сохранить прежнее состояние, показать сообщение и предложить JSON с несохранёнными изменениями.

Повреждённое хранилище не перезаписывать. Предоставить скачивание исходного содержимого и восстановление.

Неизвестную более новую схему не импортировать.

### 9.6. Миграции

Для будущего изменения схемы:

1. Прочитать старый контейнер.
2. Выполнить последовательные миграции в памяти.
3. Проверить результат.
4. Предложить скачать исходную копию.
5. Записать только после успешной проверки.

Ошибка оставляет исходные данные без изменений. В первой версии миграции из несуществующих старых схем не придумывать.

### 9.7. Несколько вкладок

Поддерживаемый режим — одна редактирующая вкладка.

По событию `storage` другая открытая вкладка получает актуальное изменение и переводится в режим без записи с предложением перезагрузить данные. Перед операцией дополнительно сравнивать `revision`.

Простую блокировку с флагом не использовать как гарантию: она может остаться после аварийного закрытия. Одновременное редактирование не поддерживается.

## 10. Печать, безопасность и совместимость

### Печать

День или отдельная поездка:

- дата и порядок мест;
- адрес, метро, расположение;
- приоритет;
- клиенты, документы и поручения;
- локальные заметки;
- готовность;
- пустые поля для результата и записей.

Историю не печатать. Фильтры списка не ограничивают состав печатного дня.

A4, `@media print`, управление скрыто, длинный текст переносится без обрезки.

### Данные клиентов

Не добавлять в модель паспортные, платёжные и другие поля сверх согласованного набора.

Хранилище и копии не шифруются приложением. Интерфейс резервного копирования сообщает, что JSON содержит данные клиентов.

Рабочий регламент:

- защищённая учётная запись компьютера;
- копии в согласованной рабочей папке;
- отсутствие публичных ссылок на рабочие JSON-копии и данные клиентов; публичная ссылка на само приложение допускается по разделу 13;
- удаление лишних копий из общих папок и «Загрузок»;
- тестирование на вымышленных или обезличенных данных.

Применимость юридических требований определяет организация отдельно. ТЗ не заявляет соответствие 152-ФЗ.

### Совместимость

Минимальные целевые версии: Chrome 120 и Edge 120. Проверить также актуальные установленные версии; номера указать в отчёте испытаний.

Проверить `TextDecoder('windows-1251')` и `Intl` с `Europe/Moscow`. При отсутствии необходимой возможности показать сообщение о неподдерживаемом браузере.

Работа localStorage для локальных файлов зависит от браузера и пути. Использовать постоянные браузер, профиль и расположение файлов. Перед переносом — JSON-копия. [Документация MDN о `file:`](https://developer.mozilla.org/en-US/docs/Web/API/Window/localStorage).

Приложение не делает сетевых запросов. Внешняя ссылка на Яндекс Карты открывает поиск адреса после действия пользователя.

Вставлять пользовательский текст через `textContent` или безопасные DOM-операции.

## 12. Тестовые материалы и приёмка

Тестовые материалы хранить отдельно от трёх поставляемых файлов страницы. Использовать вымышленные данные.

### Базовый CSV

```csv
ID задачи;Кто направил;Дата направления;Клиент;Номер листа;Место направления;Задача (сколько заявлений, что сделать);Приоритетность;Статус;Выполнение;Дата выполнения;Комментарий
```

Дополнительные наборы: Windows-1251, BOM, многострочное описание, пустой ID, повторный ID, неверная дата, неизвестный статус, конфликт результата.

## 13. Требования второго этапа

После неуспешного открытия локального HTML на iPhone пользователь согласовал статическое HTTPS-размещение трёх файлов приложения. Для мобильного запуска используется опубликованная страница в Safari; базы данных и серверной обработки задач нет, данные остаются в localStorage устройства. На компьютере прежний запуск из папки сохраняется. Хранилища локального файла, HTTPS-страницы и разных устройств отдельные; перенос выполняется JSON-копией, будущий обмен — предусмотренным объединением. Размещение по текущему адресу сохранять, чтобы не менять источник хранилища. По уточнению пользователя от 16 октября 2026 года страница доступна по ссылке без входа в ChatGPT, в том числе сотруднику без аккаунта. Публикуются только файлы приложения; задачи и резервные копии не размещаются на сайте. Первоначальный приватный режим размещения заменён публичным без изменения адреса.

Реализацию начинать после проверки на выбранном телефоне: запуск, устойчивость хранения, импорт и экспорт файлов.

Объединение копий — без графов версий и без выбора по времени устройства.

Для одинакового ID показывать различия отдельно по группам:

- исходные сведения;
- расписание;
- готовность документов;
- локальная заметка;
- результат;
- приоритет исполнителя.

Совпадающие группы сохраняются автоматически. Различающиеся группы требуют выбора версии. Новые задачи добавляются. История объединяется по ID событий без дублей.

Порядок поездок выбирается целиком для каждого различающегося дня. Конфликты справочника разбираются отдельно.

Из разных рабочих областей объединение запрещено; возможна только явная замена резервной копией. Повторный импорт идентичной копии ничего не меняет.

### Уточнения реализации обмена

В интерфейсе «Обмен данными» предусмотрены отдельные действия «Скачать JSON», «Объединить JSON» и «Восстановить JSON». Для первого переноса на второе устройство восстановить копию первого: оба устройства получают один `workspaceId`. Для последующего обмена использовать объединение. После разбора различий можно скачать объединённую копию и передать обратно на второе устройство. Автоматической синхронизации нет.

Шесть групп задачи выбираются независимо. С приоритетом исполнителя не объединять в одну группу заметку или готовность. Группа исходных сведений включает `source` и связанный `lastCsvResult`, расписание — `plannedDate` и `firstPlannedDate`, группа результата — `result` и `lastConfirmedExportResult`. Связанные снимки показаны при сравнении; они выбираются вместе с соответствующей группой. Отсутствие `localPriority` и `null` равнозначны.

Новые ID задач и отсутствующие на другом устройстве задачи сохраняются. История дополняется по ID событий; разные значения одного ID требуют отдельного выбора. При фактическом изменении группы существующей задачи добавляется событие объединения с перечнем принятых групп. Повторная обработка без новых локальных изменений с теми же выборами не добавляет событий и не увеличивает revision.

Справочник объединять по ID. Если на устройствах независимо созданы разные ID одного учреждения и есть единственное совпадение нормализованного названия, использовать местный ID и переназначить ссылки входящей копии. Различающиеся сведения учреждения требуют выбора целиком. Адрес или похожее название сами по себе не являются основанием объединения. Порядок выбирается целиком по каждому различающемуся дню, включая порядок, отсутствующий в одной копии. Сохранённые позиции не пересортировывать при объединении; новые места, отсутствующие в выбранном порядке, показывать после них по существующему правилу названия и ID. После закрытия формы действует обычный автоперенос просроченных активных задач.

Новые привязки названий, сопоставления столбцов и ожидающие CSV-выгрузки добавлять. Различия одной привязки, сопоставления, выгрузки или списка исключённых дат разбирать явно. Отчёт последнего табличного импорта, дата последней копии, дата подтверждения передачи и параметры напоминания остаются местными; чужое скачивание не считать созданием копии в этом браузере. Снимки подтверждения результатов выбираются в составе группы результата. Объединение не означает подтверждения переноса данных во внешнюю таблицу.

До применения показывать количества новых задач, новых учреждений, добавляемых событий, изменяемых задач, список добавляемых задач и значения различий с подписями «На этом устройстве» / «В JSON-файле». Предлагать скачать текущую копию без изменения её метаданных. После выбора вариантов пользователь нажимает «Проверить объединение», подтверждает и применяет. Изменение выбора сбрасывает подтверждение и готовность применения. Отмена, Escape, смена файла и неразобранные различия не записывают данные. Изменение хранилища другой вкладкой блокирует применение. Ошибка записи оставляет прежний набор и позволяет скачать кандидата.

Схема хранения остаётся 1, старые JSON первой версии принимаются. Никакие графы версий, новый сервер или базы данных не добавляются.

Первый этап принимается независимо от реализации второго.
